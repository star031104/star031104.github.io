映章 YingZhang v0.1.0：完整架构、部署与使用指南

发表于2026-09-04|更新于2026-09-14|开发报告
|浏览量:
PUBLIC RELEASE · v0.1.0

让 AI 演示从“生成几页内容”，走向可追溯、可修改、可交付的生产流程

映章是一套中文优先、本地运行的 AI 演示工作台。它从材料结构和证据出发，完成叙事规划、多候选页面生成、质量检查与定向修复，最终交付 HTML、PDF 和原生可编辑 PPTX。

一份真正要交给客户、老师或管理层的演示，必须回答比“能否生成”更难的问题：数字来自哪里？为什么这一页适合图表而不是列表？修改一页时能否保住其他页面？任务中断后能否继续？导出的 PowerPoint 是否还能由团队接着编辑？映章的设计正是从这些问题开始。

版本说明：这是映章的首个公开版本 v0.1.0，仓库以独立根提交发布，不承接此前的内部迭代版本。公开内容只包含源代码、安全配置示例、测试与架构决策，不包含 API Key、个人偏好、运行数据库、生成结果或内部版本文档。

一、项目定位：不是模板堆叠，而是演示生产系统

传统 AI PPT 工具常把链路压缩成“输入一句话—调用模型—导出文件”。这样的流程很快，却容易把事实可靠性、视觉选择、错误恢复和交付质量全部押在一次不可观察的输出上。映章把演示生产拆成若干可检查阶段，让人能够在关键节点理解发生了什么，并保留最终决定权。

证据优先

数字、结论、表格和原文图片与材料位置建立关联，来源不是最后补上的脚注，而是内容规划的输入。

过程可控

大纲、整稿、单页和修复任务均由有界节点组成，可取消、可重试、可恢复，并避免无限循环。

交付可继续

图表、表格、流程和关系图优先生成 PowerPoint 原生对象，让演示能够进入真实团队协作。

二、整体架构：四层职责，一条完整交付链路

映章采用前后端与演示引擎分离的本地架构。每一层只承担清晰的职责，并通过稳定数据结构连接。

Web 工作台负责创建项目、检查材料、审阅大纲、选择候选、编辑页面和查看质量结果。FastAPI 服务管理来源、证据、页面版本、任务、个性化与交付。演示引擎把页面场景渲染成真实浏览器画面，并生成 PDF 与 PPTX。本地数据层保存数据库、上传材料、运行产物和加密凭据。

三、生成工作流：从材料到成稿的八个阶段

需求建模

明确受众、目标、时长、语气、品牌与演示类型。

材料解析

读取章节、表格、图片、页码、工作表和来源信息。

证据组织

提取事实、数字、结论与限制条件，形成可引用内容。

叙事规划

安排页面角色、逻辑顺序、核心主张和转场关系。

页面契约

为每页定义内容预算、视觉意图、区域与对象上限。

候选渲染

按内容语义生成多个真实页面候选，而非只换模板名。

质量修复

检查溢出、碰撞、完整性、对比度、来源与许可。

人工交付

保留人工选择和局部修改，导出 HTML、PDF 与 PPTX。

每个长任务节点都保存输入摘要、输出、幂等键、最大重试次数与产物位置。服务中断后，系统可以复用仍然有效的完成节点；材料或页面内容发生变化时，旧预览会被识别为过期，避免把“看起来存在的文件”误当成当前版本。

四、材料与证据：读取文件不等于理解文件

映章支持 PDF、DOCX、XLSX、CSV、PPTX、Markdown、HTML 和常见图片。解析不只提取文字，还尽量保留文字所在的结构：Word 标题路径和图表归属、PDF 页码与可恢复表格、Excel 工作表与单位、PPTX 页面和对象关系。

材料风险映章的处理方式
长文只读取开头按相关性、结果、边界和章节覆盖选择完整内容窗口
百分比与小数混淆保留原始格式、单位和缺失值语义，不擅自补零
表格脱离章节上下文记录表格所属标题路径、列名与来源位置
限定条件在润色时丢失把否定、范围与适用边界纳入内容完整性检查
图片来源和许可不清通过素材台账记录作者、来源、许可与替代文本

五、视觉与交付：候选、评价、选择，而不是一次押注

页面生成首先判断内容关系。多指标、同单位数据适合图表；混合单位或存在缺失值时保留为表格；过程信息采用流程结构；差异信息使用对比；解释性结论则使用“判断与证据”等布局。低内容负载页面不会为了填满画布强行制造卡片。

  • 每页可生成多个真实渲染候选，并结合页面角色、内容负载和全稿节奏评分。
  • 浏览器截图检查文字裁切、对象碰撞、画布溢出、对比度和破损图片。
  • 自动修复只处理明确问题，不覆盖用户已经选定的候选与手工修改。
  • 图表、表格、时间线、流程和关系图优先输出为可编辑 PowerPoint 对象。
  • 正式导出前再次校验内容版本、素材许可、无障碍信息和交付完整性。

六、部署指南：克隆后如何在本地运行

运行环境需要 Git、Python 3.11+、Node.js 20+ 与 npm。还需要一个兼容 OpenAI API 的模型服务；它既可以是云端服务，也可以是本机模型服务。

Windows 一键启动

PowerShell
git clone https://github.com/star031104/yingzhang-ai-ppt.git
cd yingzhang-ai-ppt
Copy-Item .env.example .env
./启动项目.cmd

启动脚本会检查 Python 与 Node.js 版本，安装缺失依赖和 Chromium，构建网页并启动本地服务。完成后访问 http://127.0.0.1:8000。首次安装需要联网，日志位于 runtime/launcher/。

Windows、macOS 与 Linux 手动安装

Terminal
git clone https://github.com/star031104/yingzhang-ai-ppt.git
cd yingzhang-ai-ppt
python -m venv .venv

# Windows PowerShell
./.venv/Scripts/Activate.ps1

# macOS / Linux 改用：source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e ".[dev]"
npm ci
npx playwright install chromium

复制配置文件后，构建前端并启动完整应用：

Terminal
# Windows: Copy-Item .env.example .env
# macOS / Linux: cp .env.example .env

npm run build
python -m uvicorn app.main:app --app-dir apps/api \
  --host 127.0.0.1 --port 8000

FastAPI 会直接托管构建后的网页，因此本地生产式运行只需要一个服务进程。API 文档位于 http://127.0.0.1:8000/docs，健康检查位于 /api/v1/health。

公网部署提醒：默认监听地址仅供本机访问。若改为局域网或公网服务，需要自行配置 HTTPS、反向代理、身份认证、密钥管理、防火墙、备份和审计；首版不建议直接暴露 Uvicorn 端口。

七、模型配置与关键环境变量

首次进入应用后，在“模型配置”页面填写 OpenAI-Compatible Base URL、API Key 与模型名称，并先执行连接测试。API Key 不写入仓库，也不要放进 .env.example。不同模型服务对模型列表、视觉输入和结构化输出的兼容程度不同，建议先用少量页面验证。

环境变量默认值作用
SLIDEFORGE_DATABASE_URLsqlite:///./runtime/data/yingzhang.db本地数据库
SLIDEFORGE_ARTIFACT_ROOT./runtime/artifacts上传材料与生成产物
SLIDEFORGE_RENDER_CONCURRENCY2并行渲染页数；低内存设备可设为 1
SLIDEFORGE_LOCAL_ONLY_MODEfalse设为 true 后仅允许连接本机模型
SLIDEFORGE_PRIVATE_ACCOUNTS_MODEfalse本地个人部署保持关闭
SLIDEFORGE_OFFICE_EXECUTABLE自动发现可选 LibreOffice 可执行文件路径

八、完整用法：从新建项目到最终交付

  1. 描述任务：填写主题、受众、目标、时长、语气、页数与品牌要求。
  2. 上传材料：导入报告、数据表、既有 PPTX、网页或图片。
  3. 检查读取：核对章节、关键数字、表格、原文图和未读取部分。
  4. 审阅大纲：确认页面顺序、每页核心任务和关键证据是否合理。
  5. 生成候选：选择视觉技能，生成样张或整稿，并比较页面候选。
  6. 局部精修：修改标题、要点、图表或对象；必要时只重生成目标页。
  7. 运行门禁：处理内容遗漏、文字裁切、低对比度、来源与许可问题。
  8. 导出复核：导出 HTML、PDF 或 PPTX，并在目标 Office 环境完成终检。

“我的助手”可以按场景保存叙事和视觉偏好，也可以从用户确认过的修改中形成建议。学习默认受用户控制，支持暂停、单条遗忘、按场景清除和恢复空白工作区。每个新克隆实例都从空白数据开始，不包含维护者的习惯。

九、工程质量与目录结构

首版发布前通过 180 项 Python 测试、44 项演示引擎测试与 10 项前端测试，并完成 TypeScript 与 Vite 生产构建。测试覆盖材料解析、证据选择、任务恢复、页面版本、视觉安全、原生图表与表格、访问控制和个性化数据生命周期。

十、安全、隐私与公开发布边界

  • .env、runtime/、output/、数据库、日志、个人经验与临时文件均被版本控制排除。
  • Provider 凭据优先保存在操作系统密钥环；不可用时才回退到本地加密文件。
  • 公开仓库不包含真实账号、API Key、本机路径、个人默认偏好和内部版本报告。
  • 上传敏感材料前，应确认所连接模型服务的数据处理、留存和训练政策。
  • 如果密钥疑似泄漏，应立即在服务商后台撤销并重新生成；删除文件不能让旧密钥失效。

十一、当前边界：首版明确不承诺什么

  • 扫描版 PDF 尚不能保证可靠完成 OCR，需要先补充可检索文字。
  • 复杂公式、特殊图表、第三方字体与既有动画可能需要人工修复。
  • 模型生成内容可能包含事实错误，来源绑定不能替代人工核验。
  • 网络图片的版权、商标和人物授权仍由使用者最终确认。
  • PowerPoint、WPS 与 LibreOffice 的字体、SVG、换行和动画表现可能不同。
  • 首版接口与数据结构仍可能调整，不承诺向后兼容。
适合现在使用的场景：个人本地演示创作、课程或毕业答辩、内部报告、产品与业务方案原型，以及围绕“证据—叙事—视觉—交付”的二次开发。正式外部交付仍应保留人工终审。
